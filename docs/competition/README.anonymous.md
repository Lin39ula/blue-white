# BLUE & WHITE · 一瓷五境

以「一瓷，万象」为卷首的青花瓷交互数字展览。

## 参赛介绍（匿名版本）

本版本用于作品评选，不包含参赛者身份信息。

## 作品介绍与设计思路

泥土成形，青料成画，窑火成瓷。作品围绕青花瓷的器形、材料、制作、收藏与当代延续，以五幕叙事把观看与亲手操作连接起来。

| 章节 | 内容与体验 |
| --- | --- |
| 第一幕 · 一瓷，万象 | 卷首文字、经典 GLB 器物与开场显影；通过「观察器物」入口旋转、缩放 |
| 第二幕 · 材料解构 | 瓷胎、钴料、透明釉的艺术化分解展示，选中材料查看对应图片与说明 |
| 第三幕 · 匠艺体验 | 经典器物展示与独立 DIY 工坊，包含练泥、成型、修坯、绘青花、施釉、烧制六道工序及视频讲解 |
| 第四幕 · 经典巡礼 | 八件藏品的器物图与文字，支持箭头、缩略图及键盘切换 |
| 第五幕 · 瓷脉新生 | 「传承」「创新」两个分页面，以人物档案与当代应用图文展现青花的延续，并以结语收束 |

主线经典 GLB 的两档网页展示版本与 DIY 程序化模型相互隔离，DIY 退出后继续展示当前精度的经典器物。为符合 Cloudflare Pages 单文件 25 MiB 限制，公开站点只发布标准版与省流版；原始高规格文件应在仓库外单独归档。材料分层用于教学表达，不代表瓷器具有三个等厚的实体结构层；青花钴料绘制于瓷胎，再覆盖透明釉烧成。

本项目采用静态前端架构，不需要账号、数据库或后端服务。交互、布局和叙事组织在项目源码中实现；三维渲染、模型加载等基础能力由下列库提供，不将第三方库的底层能力计作自行实现。

## 展示规格与操作说明

- 采用响应式布局；参赛重点检查宽度为 **1920、1440、720 像素**的窗口，并检查动态调整窗口尺寸。本轮在 Chrome 129 中检查了这三种宽度，并补充 390 像素移动端检查；记录见 `docs/competition/OPTIMIZATION_REPORT.md`。
- 手册指定运行环境为 **Chrome 129**，包含正常网络与慢网测试。本轮使用独立的 Chrome for Testing 129.0.6668.100 做兼容性检查，不以新版 Chromium 代替指定版本。
- 使用滚动或顶部导航浏览章节；通过显眼的器物观察入口进入三维操作。三维交互期间使用拖动与缩放，结束观察后继续章节浏览。
- DIY 按工序导航操作，视频带播放控件；完成烧制后展示成品，可退出回到主线。
- 第四幕使用左右箭头、缩略图或左右方向键切换；第五幕切换「传承」「创新」及其图文内容。
- 模型、图片、视频的异常反馈和不同设备上的表现仍应按下述清单验收，不以构建成功代替实际浏览器测试。

## 部署：Cloudflare Pages

Cloudflare Pages 构建设置：框架预设选择 **Vite**，构建命令为 `npm run build`，发布目录为 `dist`，Node.js 版本设为 **20.19+**。项目默认以站点根路径发布；无需提交 `node_modules` 或 `dist`。

连接 Git 仓库后，Cloudflare Pages 会在推送时自动构建。若使用命令行直传，先登录 Cloudflare，再运行 `npx wrangler pages deploy dist --project-name <你的项目名>`。项目名、域名及 Cloudflare 账号尚未在本地配置，因此本仓库不保存访问令牌。

构建只发布网页视频与两档网页模型；原始高码率视频及高规格 GLB 不保留在部署仓库。`vite.config.ts` 默认的根路径适用于 Cloudflare Pages；若继续维护 GitHub Pages，工作流会显式设置 `/blue-white/` 子路径。部署路径变化时，应重新检查模型、视频、图片和 JSON 的地址。线上链接用于展示，不能替代手册要求的邮件压缩包提交。

## 本地运行与生产预览

需要 Node.js **20.19+ 或 22.12+**（对应 Vite 的运行要求），以及 npm。从 Git 克隆时还需要 Git LFS，并先确保大文件已下载：

```powershell
git lfs pull
npm ci
npm run dev -- --host 127.0.0.1 --port 5175 --strictPort
```

访问：<http://127.0.0.1:5175/>。从包含真实媒体文件的比赛压缩包解压时，无须执行 Git 命令。

构建和预览：

```powershell
npm run build
npx vite preview --host 127.0.0.1 --port 5180 --strictPort
```

访问：<http://127.0.0.1:5180/>。不要直接双击 `dist/index.html`；浏览器需要 HTTP 服务加载资源。依赖安装需要网络，安装完成后网站内容由本地静态服务提供。

## 浏览器验收与当前限制

安装测试浏览器：`npx playwright install chromium`。`scripts/model-quality-qa.mjs` 可在本地生产预览中复验两档模型与慢网回退。较早的阶段脚本仍可能使用旧端口或 GitHub Pages 子路径，运行前需对齐当前部署前缀；旧截图不能证明当前 Cloudflare 版本通过验收。

提交前应在实际部署版和本地生产预览中逐项检查：

- 五幕与结语完整浏览，正向、反向、快速滚动及导航中断后状态连续。
- 三维观察、材料选择、六道 DIY 工序、退出恢复经典 GLB、藏品及视频切换正常。
- 1920 / 1440 / 720 宽度及窗口动态缩放时，文字、视频、操作区不重叠或被裁切。
- Chrome 129 及慢网下，首屏、模型和视频有明确反馈；资源失败不阻断其他内容。
- 无阻断使用的控制台错误；Pages 子目录中的图片、JSON、GLB、视频请求正确。

当前部署包只包含标准与省流两档 GLB，任何单个发布文件均须不超过 **25 MiB**。首屏入口脚本约 **253 KB / gzip 83 KB**，三维场景代码约 **1.06 MB / gzip 295 KB**，在模型下载完成或进入 DIY 时再加载。分包仍有超过 500 KB 的构建提示，不代表总体积已消失。

模型下载显示实际字节进度，失败可独立重试；慢网等待时仍可阅读、浏览藏品与传承内容。图片提供加载与失败反馈，视频可重试。支持系统「减少动态效果」偏好、键盘焦点提示、Esc 退出观察或工坊，DIY 返回后恢复按钮焦点。

当前验收入口会自行启动生产预览（端口 5187），请先构建，再运行：

```powershell
npx playwright install chromium
node scripts/competition-qa.mjs
node scripts/submission-audit.mjs
```

设置 `CHROME_129` 为独立 Chrome 129 可执行文件的绝对路径时，验收脚本将改用该版本；设置 `MOTION_QA=1` 增加正常动画关键帧检查。默认功能矩阵使用减少动画模式，不能单独证明正常转场流畅。`QA_DIR` 可指定截图目录。测试报告同时记录浏览器版本、错误、断言结果和场景状态。

提交检查脚本生成 `docs/competition/submission-audit.json` 及 `docs/competition/README.anonymous.md`。匿名说明是供放入匿名包根目录并重命名为 `README.md` 的草稿，不替代对整个匿名包的人工审查。


本轮结果：Chrome 129 主验收 57 项、专项恢复与编辑 9 项通过；六段完整行程的结束点连续性检查通过。主验收保存 61 张截图。详见 [参赛优化与验收记录](docs/competition/OPTIMIZATION_REPORT.md)。部署及模型分级更新见 [自适应模型方案与验证](docs/competition/ADAPTIVE_MODELS.md)；历史报告对应当时构建。

## 自适应模型精度

| 选项 | 模型下载量 | 三角面数 | 用途 |
| --- | --- | --- | --- |
| 省流 | 1.53 MiB | 37,500 | 慢网 / 省流优先，贴图最大 1024 |
| 标准 | 5.24 MiB | 150,000 | 普通网络默认展示，贴图最大 2048 |

自动模式依据可用的网络信息选择模型；不支持网络信息接口时先用标准版。标准版下载超过 8 秒、平均速率低于 200 KiB/s 且仍有较多数据待下载时，取消该请求并改用省流版。手动选择不会被自动降级，选择在当前标签页会话内保留。不会预先下载两种版本。

右侧「显示精度」可手动切换；切换时重新加载模型，有加载反馈。两档网页模型每次只请求所选版本。第四、第五幕的三维场景在转场结束后按需重绘，避免不可见模型持续占用渲染循环。

网页模型由 `node scripts/optimize-model.mjs <仓库外原始GLB路径>` 生成。生成过程是有损网格与贴图优化，未使用 AI 重绘；原始模型校验资料仅保留在内部归档中。
