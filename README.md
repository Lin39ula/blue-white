## 作品介绍与设计思路

泥土成形，青料成画，窑火成瓷。作品围绕青花瓷的器形、材料、制作、收藏与当代延续，以五幕叙事把观看与亲手操作连接起来。

| 章节 | 内容与体验 |
| --- | --- |
| 第一幕 · 一瓷，万象 | 卷首文字、经典 GLB 器物与开场显影；通过「观察器物」入口旋转、缩放 |
| 第二幕 · 材料解构 | 瓷胎、钴料、透明釉的艺术化分解展示，选中材料查看对应图片与说明 |
| 第三幕 · 匠艺体验 | 经典器物展示与独立 DIY 工坊，包含练泥、成型、修坯、绘青花、施釉、烧制六道工序及视频讲解 |
| 第四幕 · 经典巡礼 | 八件藏品的器物图与文字，支持箭头、缩略图及键盘切换 |
| 第五幕 · 瓷脉新生 | 「传承」「创新」两个分页面，以人物档案与当代应用图文展现青花的延续，并以结语收束 |

主线经典 GLB（含独立的轻量展示副本）与 DIY 程序化模型相互隔离，DIY 退出后继续展示当前精度的经典器物。原始核心 GLB 未修改，选择「原始高清」可加载原件。材料分层用于教学表达，不代表瓷器具有三个等厚的实体结构层；青花钴料绘制于瓷胎，再覆盖透明釉烧成。

本项目采用静态前端架构，不需要账号、数据库或后端服务。交互、布局和叙事组织在项目源码中实现；三维渲染、模型加载等基础能力由下列库提供，不将第三方库的底层能力计作自行实现。

## 展示规格与操作说明

- 采用响应式布局；参赛重点检查宽度为 **1920、1440、720 像素**的窗口，并检查动态调整窗口尺寸。本轮在 Chrome 129 中检查了这三种宽度，并补充 390 像素移动端检查；记录见 `docs/competition/OPTIMIZATION_REPORT.md`。
- 手册指定运行环境为 **Chrome 129**，包含正常网络与慢网测试。本轮使用独立的 Chrome for Testing 129.0.6668.100 做兼容性检查，不以新版 Chromium 代替指定版本。
- 使用滚动或顶部导航浏览章节；通过显眼的器物观察入口进入三维操作。三维交互期间使用拖动与缩放，结束观察后继续章节浏览。
- DIY 按工序导航操作，视频带播放控件；完成烧制后展示成品，可退出回到主线。
- 第四幕使用左右箭头、缩略图或左右方向键切换；第五幕切换「传承」「创新」及其图文内容。
- 模型、图片、视频的异常反馈和不同设备上的表现仍应按下述清单验收，不以构建成功代替实际浏览器测试。

- Chrome 129 及慢网下，首屏、模型和视频有明确反馈；资源失败不阻断其他内容。
- 无阻断使用的控制台错误；Pages 子目录中的图片、JSON、GLB、视频请求正确。

当前 `npm run build` 通过。发布目录约 **110.1 MiB**（优化前约 717.6 MiB；其中包含原件和两个可选展示副本），核心 GLB 约 75.3 MiB，文件内容未改动。首屏入口脚本约 **253 KB / gzip 83 KB**，三维场景代码约 **1.06 MB / gzip 295 KB**，在模型下载完成或进入 DIY 时再加载。分包仍有超过 500 KB 的构建提示，不代表总体积已消失。

## 自适应模型精度

| 选项 | 模型下载量 | 三角面数 | 用途 |
| --- | --- | --- | --- |
| 省流 | 1.53 MiB | 37,500 | 慢网 / 省流优先，贴图最大 1024 |
| 标准 | 5.24 MiB | 150,000 | 普通网络默认展示，贴图最大 2048 |
| 原始高清 | 75.33 MiB | 1,500,000 | 用户主动选择的原件 |

自动模式依据可用的网络信息选择模型；不支持网络信息接口时先用标准版。标准版下载超过 8 秒、平均速率低于 200 KiB/s 且仍有较多数据待下载时，取消该请求并改用省流版。手动选择不会被自动降级，选择在当前标签页会话内保留。不会预先下载三个版本或自动升级到原始高清。

右侧「显示精度」可手动切换；切换时重新加载模型，有加载反馈。原件与两个副本均随站发布，但每次只请求所选版本。第四、第五幕的三维场景在转场结束后按需重绘，避免不可见模型持续占用渲染循环。

轻量副本由 `node scripts/optimize-model.mjs` 生成，参数与原件校验值见 `docs/competition/model-optimization.json`。生成过程是有损网格与贴图优化，未使用 AI 重绘；放大观察微小细节时可以选择原始高清。
